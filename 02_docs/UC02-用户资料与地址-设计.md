# UC02 用户资料与地址设计

本文件沿用 UC06 的独立用例设计结构，仅覆盖 Day 3 组件级设计；对象级图和 E2E 留到 Day 4。

## 接口设计

| 方法 | 路径 | 控制器 | 服务接口/实现 | 数据归属 |
|---|---|---|---|---|
| GET | `/api/user/profile`、`/api/user/me` | `UserController` | `UserService.getCurrentUserProfile` | `user` |
| PUT | `/api/user/profile` | `UserController` | `UserService.updateCurrentUserProfile` | `user` |
| GET | `/api/user/addresses` | `UserController` | `UserService.listMyAddresses` | `address` |
| POST | `/api/user/addresses` | `UserController` | `UserService.createAddress` | `address` |
| PUT | `/api/user/addresses/{addressId}` | `UserController` | `UserService.updateAddress` | `address` |
| DELETE | `/api/user/addresses/{addressId}` | `UserController` | `UserService.deleteAddress` | `address` |

## 组件级交互

源文件：[`UC02-COMP02.mmd`](diagrams/UC02-COMP02.mmd)

核心边界为 `UserController → UserServiceImpl → UserMapper/AddressMapper`。当前用户 ID 由 `JwtAuthInterceptor` 写入 `UserContext`，Service 层每次按当前用户 ID 限定查询和修改范围。

## 组件职责与规则

- `UserController`：路由、请求体校验和统一响应。
- `UserServiceImpl`：资料映射、地址归属校验、默认地址清理和删除。
- `UserMapper`：归属 `user` 表；`AddressMapper`：归属 `address` 表。
- 地址新增/修改涉及默认地址时，先清除当前用户其他默认地址，再写入目标地址。
- 修改和删除必须先按地址 ID 查询，再比较 `address.user_id` 与当前用户 ID。
- 未登录由 JWT 拦截器阻断；业务层仍保留 `UserContext` 空值保护。
