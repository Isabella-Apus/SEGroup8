# UC01 注册、登录与角色鉴权设计

本文件记录 UC01 的系统级交互设计。UC01 负责游客注册、用户登录、JWT 生成和 USER、OFFICIAL_SELLER、ADMIN 角色边界控制。

## 接口设计

| 方法 | 路径 | 使用者 | 结果 |
|---|---|---|---|
| POST | /api/auth/register | 游客 | 创建 NORMAL 状态的 USER 账号 |
| POST | /api/auth/login | 已注册用户、管理员 | 返回 JWT、角色和用户摘要 |
| GET | /api/admin/users | ADMIN | 返回管理员用户列表 |
| GET | 受保护业务接口 | 已登录用户 | 根据 JWT 和角色返回业务数据或鉴权失败 |

## JWT 跨微服务校验契约

- 签发方：`identity-governance-service`（当前单体迁移阶段由 `AuthServiceImpl`/`JwtUtils` 作为基线）。
- 签名算法：与单体 `JwtUtils` 一致，使用 JJWT 的 HMAC secret；所有服务通过环境变量注入相同 secret，禁止把真实 secret 写入代码、日志或测试 Token。
- 必选 claims：`uid`（用户 ID）、`username`（用户名）、`role`（角色）、`iat`（签发时间）、`exp`（过期时间）。
- 消费方行为：微服务先验证 Bearer 格式、签名和过期时间，再读取 `uid/username/role`；缺失或非法 Token 返回 401，角色不足由业务服务返回 403。
- 共享实现：`microservices/security-contract` 提供 `JwtTokenVerifier`、`JwtPrincipal` 和统一异常类型；每个微服务可以独立引入并校验，不读取身份服务的 `UserMapper`。
- Day 3 契约测试：覆盖后端兼容 claims、篡改 Token、过期 Token、缺失/错误 Bearer 头和弱 secret；真实业务服务接入留在微服务迁移阶段。

## 角色和鉴权规则

- 注册接口允许游客访问，密码只能以加密形式保存。
- 登录成功后签发 JWT；后续受保护接口通过 Authorization Bearer Token 识别用户。
- USER 和 OFFICIAL_SELLER 可以访问各自允许的用户或卖家接口。
- 管理员接口必须校验 ADMIN 角色，普通用户访问时返回明确的鉴权失败结果。
- 用户状态为 BANNED 时，登录不得签发有效业务 Token。

## Day 3 测试边界

- Controller API 测试覆盖注册成功、登录成功和无效请求体。
- JWT 单元测试覆盖 claims 兼容性、签名篡改、过期、缺失/错误 Bearer 头和弱 secret。
- Service 单元测试覆盖密码加密、旧密码升级和登录 Token 委托。
- 多角色真实数据库链路、微服务过滤器接入和前端 E2E 在后续回归阶段完成。
