# UC01 注册、登录与角色鉴权设计

本文件按 UC06 的“接口设计—系统交互—组件交互—职责与规则”结构编排，仅覆盖 Day 3 的组件级设计；对象级图和 E2E 留到 Day 4。

## 接口设计

| 方法 | 路径 | 控制器 | 服务接口/实现 | 数据归属 |
|---|---|---|---|---|
| POST | `/api/auth/register` | `AuthController` | `AuthService` / `AuthServiceImpl.register` | `identity-governance-service` 的 `user` |
| POST | `/api/auth/login` | `AuthController` | `AuthService` / `AuthServiceImpl.login` | `identity-governance-service` 的 `user` |
| 受保护 API | `/api/**`（认证白名单除外） | 目标业务 Controller | `JwtAuthInterceptor`、`AccessControl` | JWT 只携带身份声明，不跨库读取用户表 |

## 组件级交互

源文件：[`UC01-COMP01.mmd`](diagrams/UC01-COMP01.mmd)

组件边界为 `AuthController → AuthService → UserMapper → user`，登录成功后由 `JwtUtils` 签发令牌；受保护请求由 `JwtAuthInterceptor` 解析令牌并写入 `UserContext`，管理员业务再由 `AccessControl` 查询角色。

## 组件职责与规则

- `AuthController`：接收 HTTP 请求、触发 Bean Validation、统一包装 `Result`。
- `AuthServiceImpl`：处理用户名唯一性、密码加密/校验、账号状态和登录摘要。
- `UserMapper`：只负责 `user` 表读写；其他服务不得直接复用该 Mapper 作为跨服务调用方式。
- `JwtUtils`：使用统一密钥签发和校验 JWT，声明至少包含 `uid`、`username`、`role`、签发时间和过期时间。
- `JwtAuthInterceptor`：只负责令牌存在性和签名/过期校验，不把 JWT 中的 role 当作最终数据库授权依据。
- `AccessControl`：后台操作通过当前用户 ID 查询 `user.role`，执行 ADMIN 判断。
- `GlobalExceptionHandler`：把参数、业务和令牌异常转成 `{code,message,data}`。
