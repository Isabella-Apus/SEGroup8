# UC01 注册、登录与角色鉴权设计

本文件记录 UC01 的系统级交互设计。UC01 负责游客注册、用户登录、JWT 生成和 USER、OFFICIAL_SELLER、ADMIN 角色边界控制。

## 接口设计

| 方法 | 路径 | 使用者 | 结果 |
|---|---|---|---|
| POST | /api/auth/register | 游客 | 创建 NORMAL 状态的 USER 账号 |
| POST | /api/auth/login | 已注册用户、管理员 | 返回 JWT、角色和用户摘要 |
| GET | /api/admin/users | ADMIN | 返回管理员用户列表 |
| GET | 受保护业务接口 | 已登录用户 | 根据 JWT 和角色返回业务数据或鉴权失败 |

## 系统级交互

~~~mermaid
sequenceDiagram
    autonumber
    actor Visitor as 游客/用户
    participant Platform as 交易平台
    participant Admin as 管理员
    Visitor->>Platform: POST /api/auth/register
    Platform-->>Visitor: code=0，注册成功
    Visitor->>Platform: POST /api/auth/login
    Platform-->>Visitor: JWT + USER/SELLER 角色
    Visitor->>Platform: 携带 JWT 访问受保护接口
    Platform-->>Visitor: 返回业务数据或鉴权失败
    Admin->>Platform: POST /api/auth/login
    Platform-->>Admin: JWT + ADMIN 角色
    Admin->>Platform: GET /api/admin/users
    Platform-->>Admin: 返回管理员数据
~~~

## 角色和鉴权规则

- 注册接口允许游客访问，密码只能以加密形式保存。
- 登录成功后签发 JWT；后续受保护接口通过 Authorization Bearer Token 识别用户。
- USER 和 OFFICIAL_SELLER 可以访问各自允许的用户或卖家接口。
- 管理员接口必须校验 ADMIN 角色，普通用户访问时返回明确的鉴权失败结果。
- 用户状态为 BANNED 时，登录不得签发有效业务 Token。
