# UC03 商家申请与审核设计

本文件沿用 UC06 的独立用例设计结构，仅覆盖 Day 3 组件级设计；对象级图和 E2E 留到 Day 4。

## 接口设计

| 方法 | 路径 | 控制器 | 服务接口/实现 | 数据归属 |
|---|---|---|---|---|
| POST | `/api/user/merchant-application` | `UserController` | `UserService.submitMerchantApplication` → `MerchantApplicationService.submit` | `merchant_application` |
| GET | `/api/user/merchant-application/me` | `UserController` | `UserService.getMyMerchantApplication` → `MerchantApplicationService.getMyApplication` | `merchant_application` |
| GET | `/api/admin/merchant-applications` | `AdminMerchantApplicationController` | `MerchantApplicationService.pageForAdmin` | `merchant_application`、`user` |
| POST | `/api/admin/merchant-applications/{id}/approve` | `AdminMerchantApplicationController` | `MerchantApplicationService.approve` | `merchant_application`、`user`、`shop`、`notification`、`admin_audit_log` |
| POST | `/api/admin/merchant-applications/{id}/reject` | `AdminMerchantApplicationController` | `MerchantApplicationService.reject` | `merchant_application`、`notification`、`admin_audit_log` |

## 系统级交互

~~~mermaid
sequenceDiagram
    autonumber
    actor User as 普通用户
    actor Admin as 管理员
    participant Platform as 交易平台
    User->>Platform: POST /api/user/merchant-application
    Platform-->>User: 返回待审核申请
    User->>Platform: GET /api/user/merchant-application/me
    Platform-->>User: 返回申请状态
    Admin->>Platform: GET /api/admin/merchant-applications
    Platform-->>Admin: 返回申请队列
    alt 审核通过
        Admin->>Platform: POST /{applicationId}/approve
        Platform-->>User: 角色升级为 OFFICIAL_SELLER
    else 审核拒绝
        Admin->>Platform: POST /{applicationId}/reject
        Platform-->>User: 申请拒绝并保存原因
    end
    Platform-->>Admin: 写入管理员审计记录
~~~

## 组件级交互

~~~mermaid
sequenceDiagram
  actor Applicant as 普通用户
  actor Admin as 管理员
  participant UAPI as UserController
  participant AAPI as AdminMerchantApplicationController
  participant Svc as MerchantApplicationServiceImpl
  participant Apps as MerchantApplicationMapper
  participant Users as UserMapper
  participant Shops as ShopMapper
  participant Notify as NotificationMapper
  participant Audit as AdminAuditLogService
  participant DB as merchant_application/user/shop/notification/admin_audit_log

  Applicant->>UAPI: POST /api/user/merchant-application
  UAPI->>Svc: submit(request)
  Svc->>Apps: 查询本人最新申请
  Apps->>DB: SELECT merchant_application
  alt 无待审/已通过申请
    Svc->>Apps: insert(status=0)
    Apps->>DB: INSERT merchant_application
    UAPI-->>Applicant: success
  else 已有有效申请
    UAPI-->>Applicant: 400 重复申请
  end

  Admin->>AAPI: GET /api/admin/merchant-applications
  AAPI->>Svc: pageForAdmin(query)
  Svc->>Apps: selectPage
  Apps->>DB: SELECT merchant_application
  AAPI-->>Admin: 申请列表

  Admin->>AAPI: POST /{id}/approve 或 /reject
  AAPI->>Svc: approve(id) / reject(id, reason)
  Svc->>Apps: 更新申请状态和原因
  Apps->>DB: UPDATE merchant_application
  alt approve
    Svc->>Users: 升级 OFFICIAL_SELLER
    Users->>DB: UPDATE user
    Svc->>Shops: upsert shop
    Shops->>DB: INSERT/UPDATE shop
  end
  Svc->>Notify: insert审核结果通知
  Notify->>DB: INSERT notification
  AAPI->>Audit: record审核动作
  Audit->>DB: INSERT admin_audit_log
  AAPI-->>Admin: success
~~~


用户提交由 `UserController/UserService` 转交 `MerchantApplicationServiceImpl`；管理员审核由 `AdminMerchantApplicationController` 调用同一领域服务，控制器在成功后调用 `AdminAuditLogService`。通过分支还会写 `user`、`shop`、`notification`。

## 组件职责与规则

- `UserController`：负责用户侧请求体校验和本人查询。
- `AdminMerchantApplicationController`：负责管理员列表、通过、拒绝路由，并记录审核动作。
- `MerchantApplicationServiceImpl`：负责申请状态机、管理员权限、角色升级、店铺 upsert 和通知。
- `merchant_application` 是申请状态的唯一来源；`status=0/1/2` 分别表示待审/通过/拒绝。
- `user.role` 的 `OFFICIAL_SELLER` 变更只能发生在通过分支。
- `shop`、`notification` 和 `admin_audit_log` 是通过/拒绝后的联动结果，不改变申请主状态的判定。
