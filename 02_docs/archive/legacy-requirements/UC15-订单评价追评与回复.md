# REQ15 / UC15 订单评价、追评与商家回复

## 业务目标

买家能够对本人待评价订单提交订单级或逐商品首评，并在首评后追加一次追评；拥有被评商品的卖家能够回复首评，评价数据可在买家和卖家页面查询。

## 参与者、触发条件和前置条件

- 主要参与者：订单买家、商品卖家。
- 触发条件：买家在待评价订单提交评价或在“我的评价”追加追评；卖家在评价管理页回复。
- 前置条件：首评要求订单属于买家且状态为 `RECEIVED(3)`；订单包含可评价商品；评分为 1–5，内容非空且不超过 500 字；追评要求对应首评存在且尚未追评；回复人必须拥有被评价商品。

## 主成功流程

1. 买家打开订单详情，选择订单级统一评价或逐商品评价。
2. 系统校验订单归属、待评价状态、评价商品属于该订单且未提交过首评。
3. 系统为每个商品写入 `ORIGINAL` 评价，保存商品类型、商品 ID、评分和内容。
4. 系统将订单更新为 `COMPLETED(4)`，记录完成时间并通知相关卖家。
5. 买家在评价列表查看自己的首评。
6. 卖家在评价管理页查看本人商品的评价，提交回复；系统保存回复内容和时间。
7. 买家针对已有首评提交一次 `FOLLOWUP` 追评，并在评价列表查看完整对话。

## 备选流程

- A1：订单级评价将相同评分和内容应用于订单内所有商品。
- A2：逐商品评价允许每个商品使用不同评分和内容。
- A3：买家也可不填写评价而直接完成待评价订单；该操作仅完成订单，不新增评价。
- A4：卖家列表可按评分、关键词、时间和回复状态筛选本人商品评价。

## 异常流程

- E1：订单不属于当前用户或商品不属于该订单，返回 403/400。
- E2：订单不是待评价状态，拒绝首评。
- E3：重复首评、重复逐商品首评或重复追评，拒绝且不插入新记录。
- E4：没有首评时提交追评，返回业务错误。
- E5：非商品所有者回复评价，返回 403；评价不存在时返回 404。
- E6：评分越界、内容为空或超过长度限制，返回参数校验错误。

## 可验证结果

| 验证通道 | 可验证结果 |
|---|---|
| 页面 | `OrderDetailView.vue` 提交后订单变为已完成；`MyReviewView.vue`/`MyReviewsView.vue` 展示首评、追评和卖家回复；`MerchantReviewsView.vue` 展示本人商品评价。 |
| 接口 | 首评接口返回 `orderStatus=4`；`GET /api/review/my` 和卖家列表返回对应评价；追评/回复接口返回 `code=0`；重复或越权请求返回明确业务码。 |
| 数据库 | `review` 中首评为 `ORIGINAL`、追评为 `FOLLOWUP`；卖家回复和时间写在首评记录；`order_info.order_status=4` 且完成时间非空；同一商品每类评价数量满足唯一性规则。 |
| 日志 | 新评价通知可关联订单和卖家；异常请求不应产生评价写入或订单状态变化。 |

## 验收条件

- AC15-01：本人待评价订单可提交首评并原子完成订单。
- AC15-02：逐商品评价只能覆盖订单内商品，重复首评被拒绝。
- AC15-03：每个首评最多一次追评，只有商品所有者可回复。
- AC15-04：买家和卖家查询结果与 `review`、`order_info` 数据一致。
