# UC24 会话与消息

Parent UC：#63。Day3–Day5 Task：#145。

买家和卖家可以围绕商品创建站内会话并双向发送消息。系统只向会话参与者展示会话和历史记录，收到历史记录后把当前用户的未读消息标记为已读。第三方用户不能读取、发送或修改该会话的数据。

## 规则

- 同一买家、卖家、来源类型和来源 ID 只保留一个会话。双方重复创建时返回同一个会话。
- 商品会话的卖家必须是商品所属店铺的所有者。系统拒绝目标用户与实际卖家不一致的请求。
- 会话列表只返回当前用户作为买家或卖家的记录。
- 只有买家和卖家可以读取历史、发送消息及触发已读更新。
- 消息去除首尾空白后不能为空，长度不能超过 1000 个字符。校验失败时不写 `chat_message` 或 `notification`。
- 任一方向存在拉黑关系时禁止发送，且不改变消息历史。
- 消息、会话最后消息和站内通知在事务内持久化。实时推送是尽力交付；推送异常不能回滚已提交消息，也不能把成功写入返回成失败。
- 新消息通知发给接收方。卖家通知跳转 `/merchant/messages`，普通用户通知跳转 `/messages`。

## Acceptance

1. 买家创建商品会话，卖家再次创建返回相同会话 ID；双方列表包含该会话，第三方列表不包含。
2. 买家和卖家能在 Microsoft Edge 页面双向发送，刷新后仍能看到两条消息。
3. 读取历史后接收方未读消息变为已读，并生成面向接收方的正确通知。
4. 第三方直接读取或发送返回业务码 403，消息数量不变。
5. 空白、1001 字符和任一方向拉黑场景均不写消息或通知。
6. 模拟实时推送异常时，API 仍返回成功，消息和通知保留在数据库。
