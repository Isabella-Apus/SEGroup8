# UC23 钱包与结算

Parent UC：#62。Day3–Day5 Task：#144。历史证据：#92。

登录用户可以查询个人钱包、充值并查看本人流水。系统把官方商品结算到卖家的经营账户，把个人账户与经营账户分开存储和查询。

## 业务规则

- 用户首次查询财务看板时，系统创建个人余额和经营余额均为 0 的 `balance` 记录。
- 充值金额至少为 0.01。充值只增加 `personal_balance`，并写入 `PERSONAL / RECHARGE` 流水。
- 官方商品确认收货后，系统只增加店主的 `business_balance`，并写入 `BUSINESS / INCOME_BUSINESS` 流水。流水保存订单号、金额和结算后余额。
- 个人流水和经营流水都从当前 JWT 用户取 `user_id`。普通用户访问经营流水接口得到业务码 403。
- 余额更新使用 `version` 乐观锁。冲突后服务重新读取余额，最多尝试三次，避免并发入账覆盖金额。
- 余额更新和流水插入使用同一 Spring 事务。流水插入失败时，系统回滚余额。
- 订单状态和版本条件只允许一次确认收货。重复确认不能再次结算。
- 结算后退款从卖家经营账户扣回同额资金，并把资金写回买家个人账户。两条 `REFUND_BACKFLOW` 流水的金额和为 0。

## 接口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/finance/dashboard` | 查询并按需初始化当前用户余额 |
| POST | `/api/finance/recharge` | 给当前用户个人账户充值 |
| GET | `/api/finance/my-wallet/records` | 查询当前用户个人流水 |
| GET | `/api/finance/business/records` | 查询官方卖家经营流水 |
| POST | `/api/order/{id}/confirm-receive` | 确认收货并释放担保资金 |

## Acceptance

买家在个人资料页充值后，页面显示增加后的个人余额和充值流水；刷新后数值不变。普通买家不能读取经营流水。官方商品完成支付、发货和确认收货后，卖家财务看板显示一笔带订单号的经营账户入账；重复确认收货不增加余额或流水。
