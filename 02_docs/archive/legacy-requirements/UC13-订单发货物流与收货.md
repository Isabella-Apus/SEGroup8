# REQ13 / UC13 订单发货、物流与收货

## 业务目标

卖家能够对本人待发货订单发货并生成物流轨迹，买家能够查看轨迹并确认收货；物流到达且超时未确认时，系统可自动确认并完成资金结算。

## 参与者、触发条件和前置条件

- 主要参与者：商品卖家、订单买家。
- 协作参与者：定时任务、物流路径引擎、结算模块、通知与实时推送机制。
- 触发条件：卖家点击发货或推进物流；买家查看物流或确认收货；系统扫描到自动确认截止时间已到。
- 前置条件：订单已支付且待发货；发货人拥有订单商品；订单已经拆分为可独立履约的单商品订单；收货人是订单买家；物流目的省份可映射。

## 主成功流程

1. 卖家在订单页面填写或确认发货省市并提交发货。
2. 系统校验卖家所有权和 `PENDING_SHIP(1)` 状态，将订单更新为 `SHIPPED(2)`。
3. 系统按发货地和收货省份查找或生成物流路径模板，并写入首条“已揽收”轨迹。
4. 系统通知买家，买家可查询按时间排序的物流轨迹。
5. 卖家逐次推进物流节点；到达终点时订单物流状态变为 `ARRIVED`，记录到达时间和自动确认截止时间。
6. 买家点击确认收货，系统将订单更新为 `RECEIVED(3)`。
7. 系统按商品类型释放托管资金，写入余额和交易流水，并设置新品售后期限。
8. 系统通知卖家订单已收货并进入待评价。

## 备选流程

- A1：发货请求未填写发货地时，新品使用店铺仓库地址，无法解析时使用默认北京。
- A2：重复发货已处于 `SHIPPED` 时，仅确保物流模板和首条轨迹存在，不重复改变状态。
- A3：物流到达后买家未操作，定时任务在截止时间到达时自动确认收货并执行相同结算规则。
- A4：不同商品类型分别结算到商家余额或个人余额。

## 异常流程

- E1：非商品卖家发货或推进物流，返回 403。
- E2：遗留合并订单包含多个商品明细时拒绝直接发货，返回 409，并提示先拆分。
- E3：非待发货订单首次发货、非待收货订单确认收货，返回业务错误。
- E4：物流模板不存在、节点为空、目的地区域无法映射或轨迹已到终点，返回明确错误。
- E5：非买家且非卖家查询物流，返回 403。
- E6：余额结算或轨迹写入失败时，事务回滚，避免订单状态领先于持久化结果。

## 可验证结果

| 验证通道 | 可验证结果 |
|---|---|
| 页面 | `MerchantOrdersView.vue` 显示已发货和推进物流；`OrderView.vue`、`OrderDetailView.vue`、`OrderTimeline.vue` 显示待收货、轨迹和待评价。 |
| 接口 | 发货接口返回 `orderStatus=2`；物流查询返回递增轨迹；确认收货返回 `orderStatus=3`；越权请求返回 403 业务码。 |
| 数据库 | `order_info` 的发货、物流、到达、自动确认和收货字段正确；`logistics_path_template`/`logistics_trace` 有对应记录；结算后 `balance`/`transaction_record` 金额正确。 |
| 日志 | 定时任务、通知和实时推送日志可关联订单 ID；自动确认失败会记录告警并允许下次扫描重试。 |

## 验收条件

- AC13-01：卖家发货生成首条物流轨迹，只有订单卖家可推进。
- AC13-02：买家能够按顺序查看物流并确认收货，越权用户不可查看。
- AC13-03：人工确认和超时自动确认执行一致的状态与结算规则。
- AC13-04：重复发货、物流终点和遗留合并订单得到可预测、可测试的结果。
