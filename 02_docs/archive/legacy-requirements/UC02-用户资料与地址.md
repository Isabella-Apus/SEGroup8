# REQ02 / UC02 用户资料与地址

## 业务目标

允许登录用户维护自己的公开资料和收货地址，并确保地址归属、默认地址唯一性和删除结果可验证。

## 参与者、前置条件与触发

- 参与者：已登录普通用户、官方卖家。
- 前置条件：JWT 有效；目标用户和地址记录存在。
- 触发：用户打开资料/地址页面，执行查询、新增、修改或删除。

## 接口与成功结果

| 方法 | 路径 | 结果 |
|---|---|---|
| GET | `/api/user/profile`、`/api/user/me` | 返回当前用户资料 |
| PUT | `/api/user/profile` | 只修改当前用户资料 |
| GET | `/api/user/addresses` | 返回当前用户地址列表 |
| POST | `/api/user/addresses` | 新增当前用户地址 |
| PUT | `/api/user/addresses/{addressId}` | 修改本人地址 |
| DELETE | `/api/user/addresses/{addressId}` | 删除本人地址 |

## 主成功流

1. 用户携带 JWT 查询自己的资料或地址。
2. 用户提交资料修改或完整地址字段。
3. 系统根据当前用户 ID 写入 `user` 或 `address`。
4. 设置默认地址时清除该用户的其他默认地址。
5. 删除成功后再次查询不返回该地址。

## 备选与异常流

- 未登录：资料和地址接口返回 `401`。
- 手机号、收件人或地址字段不合法：返回 `400`，不写库。
- 地址不属于当前用户：返回 `404/403` 业务失败，不修改他人数据。
- 地址不存在：返回明确的资源不存在错误。
- 多次设置默认地址：最终同一用户最多保留一个默认地址。

## 可验证结果

- AC02-01：资料查询和修改只影响当前用户。
- AC02-02：地址新增、查询、修改字段一致。
- AC02-03：同一用户默认地址唯一。
- AC02-04：不能操作他人地址，删除后地址不可见。
