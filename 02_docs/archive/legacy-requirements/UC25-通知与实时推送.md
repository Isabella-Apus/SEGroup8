# UC25 通知与实时推送

## 目标

登录用户能够查看自己的通知，按买家或卖家范围筛选，标记单条或全部通知为已读。新通知写库后通过 WebSocket 推送给目标用户；连接中断时不丢数据，客户端重连后从通知列表补拉缺失记录。

## 前置条件

- 用户已登录并持有有效 JWT。
- 通知表可写，HTTP API 与 `/ws/realtime` 由同一 Nginx 入口转发。
- 浏览器启用真实数据源，未使用 mock handler。

## 主流程

1. 用户登录，客户端携带 JWT 建立 WebSocket。
2. 页面请求 `GET /api/notifications`，只返回当前用户的数据。
3. 业务服务创建通知并先写入 `notification` 表。
4. 服务向通知归属用户发送 `NOTIFICATION_CREATED`。
5. 页面收到事件并显示未读通知。
6. 用户标记单条通知已读，刷新页面后仍为已读。

## 重连补偿

1. 浏览器连接中断，服务端继续持久化新通知。
2. 客户端按退避策略重连。
3. 重连成功时客户端发出 `REALTIME_RECONNECTED` 本地事件。
4. 通知页面重新查询列表，补回断线期间遗漏的通知。

## 权限与异常

- 查询结果必须按当前登录用户隔离。
- `scope=buyer|seller` 只影响当前用户的筛选和批量已读。
- 标记他人或不存在的通知均返回业务码 404，不泄露记录是否属于他人。
- 缺失、篡改或过期 JWT 的 WebSocket 握手返回 401。
- 实时推送异常不得回滚已经持久化的通知。

## 验收标准

- [x] 当前用户查询、范围筛选、单条已读、全量及范围已读均有自动化覆盖。
- [x] 他人通知不会出现在列表中，也不能被当前用户标记已读。
- [x] 创建通知只向目标用户推送；推送异常后记录仍存在。
- [x] WebSocket 有效 JWT 成功，缺失、无效、过期 JWT 失败。
- [x] 真实 Edge 完成登录、连接、触发通知、页面实时显示、标记已读和刷新持久化。
- [x] 真实 Edge 在断线期间遗漏通知，重连后无需手动刷新即可补拉。
