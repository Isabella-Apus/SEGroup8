# UC05 举报、拉黑与信用治理设计

本文件沿用 UC06 的独立用例设计结构，仅覆盖 Day 3 组件级设计；对象级图和 E2E 留到 Day 4。

## 接口设计

| 方法 | 路径 | 控制器 | 服务接口/实现 | 数据归属 |
|---|---|---|---|---|
| POST/GET | `/api/report-block/report`、`/report/my` | `ReportBlockController` | `ReportBlockService.submitReport/myReports` | `user_report` |
| POST/DELETE/GET | `/api/report-block/block/**` | `ReportBlockController` | `ReportBlockService.block/unblock/list/check` | `user_block` |
| GET | `/api/credit/me`、`/api/credit/{userId}` | `CreditController` | `CreditService.getMyCredit/getCreditInfo` | `user`、`credit_score_log` |
| GET | `/api/admin/reports` | `AdminReportController` | `ReportBlockService.adminListReports` | `user_report` |
| POST | `/api/admin/reports/audit` | `AdminReportController` | `ReportBlockService.adminAuditReport` + `CreditService.onReportUpheld` | `user_report`、`user`、`credit_score_log` |
| POST | `/api/admin/reports/credit-adjust` | `AdminReportController` | `CreditService.adminAdjust` | `user`、`credit_score_log`、`admin_audit_log` |
| GET | `/api/admin/audit-logs` | `AdminAuditLogController` | `AdminAuditLogService.pageLogs` | `admin_audit_log` |

用户举报/拉黑由 `ReportBlockController → ReportBlockServiceImpl` 处理；管理员审核先由 `AccessControl` 校验身份，再调用举报服务，成立分支调用 `CreditService`；Controller 最后写审计日志。

## 组件职责与规则

- `ReportBlockController`：用户举报、拉黑及关系查询路由。
- `AdminReportController`：管理员权限、举报审核和信用调整路由；信用调整使用 query parameters，与实际 Controller 保持一致。
- `ReportBlockServiceImpl`：目标存在、自操作、重复举报/拉黑、状态转换和记录写入。
- `CreditServiceImpl`：按交易场景选择信用维度，执行 0-100 边界保护并写 `credit_score_log`。
- `AdminAuditLogService`：记录举报审核和信用调整操作。
- `user_report`、`user_block`、`credit_score_log`、`admin_audit_log` 均属于身份治理服务；微服务拆分后通过内部契约访问。
