# UC25 通知、已读与实时推送组件级图

- 图编号：`COMP-UC25-01`
- 父用例：`UC25`（GitHub #64）
- 子任务：GitHub #95

```mermaid
sequenceDiagram
    actor User as 用户
    participant UI as NotificationPage
    participant API as NotificationController
    participant NS as NotificationService
    participant NM as NotificationMapper
    participant DB as notifications
    participant Push as RealtimePushService
    participant WS as WebSocketSession

    User->>UI: 查看通知/标记已读
    UI->>API: GET /api/notifications
    API->>NS: listMyNotifications(userId, scope)
    NS->>NM: 按 userId 查询
    NM->>DB: SELECT ... WHERE user_id = ?
    DB-->>NM: 本人通知
    NM-->>NS: Notification 列表
    NS-->>API: NotificationVO 列表
    API-->>UI: 200

    User->>UI: 标记通知已读
    UI->>API: PUT /api/notifications/{id}/read
    API->>NS: markRead(userId, id)
    NS->>NM: 校验通知归属
    alt 通知属于当前用户
        NS->>NM: UPDATE is_read = 1 AND user_id = ?
        NM->>DB: 更新本人通知
        DB-->>UI: 可由接口/数据库验证 is_read=1
    else 越权或通知不存在
        NS-->>API: 404 通知不存在
        API-->>UI: 不泄露他人通知
    end

    Note over NS,WS: 新通知创建后的实时链路
    NS->>NM: INSERT notification
    NM->>DB: 持久化未读通知
    NS->>Push: pushToUser(userId, NOTIFICATION_CREATED, payload)
    Push->>WS: TextMessage(JSON)
    WS-->>UI: 实时刷新；断线时仍可通过数据库补拉
```

## 可验证结果

- 接口：只能查询、更新当前登录用户的通知；越权标记返回 404。
- 数据库：`notification.user_id` 与登录用户一致，成功标记后 `is_read=1`。
- WebSocket：合法 JWT 握手后属性中写入 `uid`；缺失或非法 token 返回 401。
- 日志：推送失败不影响通知持久化，客户端重连后通过通知列表补偿。
