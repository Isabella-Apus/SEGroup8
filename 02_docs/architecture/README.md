# 微服务架构交付索引

本目录是微服务阶段的架构事实入口。A-E 是团队分工、需求追踪和测试统计使用的交付域；运行时服务边界以这里的设计为准，二者不能混为一谈。

| 文档 | 用途 | 状态 |
|---|---|---|
| [微服务划分与依赖设计](microservice-boundaries.md) | 当前实现盘点、6 个目标服务、Domain A 认证依赖、迁移顺序和服务关系图 | 目标设计；Domain B 四个内部模块已部分实现 |
| [服务 API 清单](service-api-catalog.md) | 当前公开接口的唯一目标归属，以及后续内部 API/事件契约 | 当前路由已按源码盘点；内部契约为目标设计 |
| [数据库表归属方案](database-ownership.md) | 单体 33 张逻辑业务表和现有微服务表的唯一写入者、跨服务引用规则 | 归属已冻结；物理拆库待迁移 |

目标架构中的 6 个服务都必须能独立构建、测试、制作镜像和通过 Helm 单独部署；仅在同一个单体中划分 package，或只拆出数据库 schema，均不算微服务完成。

审计时必须分别表述：

- `CURRENT`：仓库当前可运行代码；
- `IMPLEMENTED_MICROSERVICE`：`microservices/` 中已经能独立构建和测试的模块；
- `TARGET`：后续迁移边界，不能当作运行通过证据；
- `NOT_RUN`：尚未取得对应运行记录。
