# REQ03 / UC03 商家入驻申请与审核

## 业务目标

允许普通用户提交商家入驻申请，由管理员审核；通过后升级为 `OFFICIAL_SELLER` 并建立/补全店铺，拒绝后保留原因且不改变原角色。

## 参与者、前置条件与触发

- 参与者：普通用户、管理员、通知服务。
- 前置条件：用户已登录；申请资料完整；管理员账号有效。
- 触发：用户提交入驻申请，或管理员查看并处理申请队列。

## 接口与成功结果

| 方法 | 路径 | 结果 |
|---|---|---|
| POST | `/api/user/merchant-application` | 创建待审核申请 |
| GET | `/api/user/merchant-application/me` | 查询本人最新申请 |
| GET | `/api/admin/merchant-applications` | 管理员分页查询申请 |
| POST | `/api/admin/merchant-applications/{applicationId}/approve` | 申请通过、角色升级、店铺/通知/审计联动 |
| POST | `/api/admin/merchant-applications/{applicationId}/reject` | 申请拒绝并保存原因 |

## 主成功流

1. 普通用户提交店名、分类、证件、营业执照、仓库和联系人信息。
2. 系统校验字段并写入 `merchant_application(status=0)`。
3. 管理员查看待审核列表。
4. 管理员通过申请，系统将用户角色升级为 `OFFICIAL_SELLER`，建立或更新 `shop`，发送通知并记录审计。
5. 用户查询本人申请状态。

## 备选与异常流

- 申请字段缺失或格式不正确：返回 `400`，不新增申请。
- 用户存在待审核/已通过申请：拒绝重复提交。
- 非管理员访问列表或审核接口：返回 `403`。
- 申请记录不存在：返回 `404`。
- 拒绝审核：状态改为拒绝，保存原因，用户角色不升级。
- 已通过申请再次通过：保持幂等，不重复产生核心升级结果。

## 可验证结果

- AC03-01：用户可以提交并查询自己的申请。
- AC03-02：只有管理员可以查看申请队列并执行审核。
- AC03-03：拒绝保存原因，申请人角色仍为原角色。
- AC03-04：通过升级为 `OFFICIAL_SELLER`，店铺、通知和审计结果可查。
