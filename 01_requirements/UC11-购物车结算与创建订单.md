# REQ11 / UC11 购物车结算与创建订单

## 业务目标

买家能够从购物车或商品详情发起结算，选择本人收货地址和可用优惠券，生成金额、商品明细、收货信息和库存占用均一致的待付款订单。

## 参与者、触发条件和前置条件

- 主要参与者：已登录买家。
- 协作参与者：商品卖家、优惠券模块、通知与幂等机制。
- 触发条件：买家在购物车点击“去结算”，或在商品详情点击立即购买并确认提交。
- 前置条件：买家身份有效；至少选择一件商品；商品存在且为在售状态；购买数量为正且库存充足；收货地址属于当前买家；买家与卖家之间不存在交易屏蔽；所选优惠券满足使用范围、门槛和有效期。

## 主成功流程

1. 买家选择商品、数量、收货地址，可选优惠券并填写备注。
2. 系统合并请求中重复的商品项，重新读取商品价格、状态和库存。
3. 系统校验买家交易权限、收货地址归属和优惠券资格。
4. 系统逐项扣减库存；库存降为零时将商品改为下架。
5. 系统按商品价格计算总金额，并计算优惠券折扣、商家承担额、平台承担额和应付金额。
6. 系统创建 `PENDING_PAY(0)`、`pay_status=0` 的订单主记录和订单明细。
7. 系统占用优惠券并返回订单号、金额、收货信息和商品明细。
8. 页面清理本次已结算的购物车项目，并引导买家支付。

## 备选流程

- A1：买家未显式选择地址时，系统使用本人默认地址；没有默认地址时使用本人最近地址。
- A2：买家未选择优惠券时，应付金额等于商品总金额。
- A3：请求中同一商品出现多次时，系统合并数量后统一校验和扣减库存。
- A4：单个商品立即购买与购物车批量结算共用创建订单接口。

## 异常流程

- E1：商品不存在或已下架，返回明确业务错误，不创建订单。
- E2：库存不足、数量非法或商品为空，拒绝请求并回滚本事务内已发生的库存修改。
- E3：地址不存在或不属于当前买家，拒绝请求。
- E4：买家购买本人店铺商品，或买卖双方存在屏蔽关系，拒绝交易。
- E5：优惠券无效、已被占用、未达门槛或不适用于当前店铺，拒绝请求并保持订单、库存和券状态一致。
- E6：重复提交携带相同幂等键时，返回首次请求结果，不重复创建订单或扣减库存。

## 可验证结果

| 验证通道 | 可验证结果 |
|---|---|
| 页面 | `CartView.vue` 或 `ProductDetailView.vue` 显示创建成功；跳转后的订单金额、地址和商品明细与结算确认一致。 |
| 接口 | `POST /api/order/create` 返回 `code=0`、订单 ID/订单号、`orderStatus=0`、`payStatus=0`、金额和明细。 |
| 数据库 | `order_info` 新增一条主记录；`order_item` 条数与合并后的商品项一致；`product.stock` 正确扣减；使用优惠券时 `user_voucher` 被占用且订单折扣字段一致。 |
| 日志 | API 日志含 trace ID；幂等请求可在 `idempotency_record` 追溯，失败事务不得留下半成品订单。 |

## 验收条件

- AC11-01：合法结算生成唯一待付款订单，服务端金额不依赖前端传入价格。
- AC11-02：库存扣减、订单主从记录和优惠券占用保持事务一致。
- AC11-03：无库存、越权地址、禁止交易、无效优惠券和重复提交均得到可测试结果。
- AC11-04：页面、接口、数据库和日志至少可从两种通道交叉验证创建结果。
