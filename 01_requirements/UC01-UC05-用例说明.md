# 成员 A：REQ01/UC01–REQ05/UC05 用例说明

- 负责人：成员 A / znn

- 对应服务：`identity-governance-service`

## REQ01 / UC01 注册、登录和角色鉴权

### 业务目标

允许游客注册账号，允许已注册用户登录，并依据 `USER`、`OFFICIAL_SELLER`、`ADMIN` 角色限制后台管理接口访问。

### 参与者、触发与前置条件

- 参与者：游客、普通用户、官方卖家、管理员。
- 触发条件：游客提交注册表单；用户提交用户名和密码；用户访问需要登录或管理员权限的接口。
- 前置条件：后端和数据库可访问；用户名未被占用；管理员测试账号已初始化。

### 主成功流程

1. 游客提交用户名、密码、昵称及可选联系方式。
2. 系统校验必填字段、密码长度和联系方式格式。
3. 系统以加密形式保存密码，创建 `USER`、`NORMAL` 用户。
4. 用户提交正确账号密码登录。
5. 系统签发 JWT，返回角色和用户摘要。
6. 用户携带 JWT 请求受保护资源；管理员携带 ADMIN JWT 访问管理员资源。

### 备选与异常流程

- 用户名已存在：拒绝注册，不产生重复用户。
- 必填字段为空、密码过短或手机号格式错误：拒绝注册并返回明确错误码。
- 密码错误或账号不存在：拒绝登录，不签发有效 JWT。
- 无 token 或 token 过期：拒绝受保护请求。
- USER/SELLER 访问管理员接口：返回权限拒绝，不能读取或修改管理数据。

### 可验证结果与验收条件

- AC01-01：注册成功后 `user` 新增一条 `role=USER,status=NORMAL` 记录，密码不可为明文。
- AC01-02：正确密码登录返回非空 JWT、角色和用户摘要。
- AC01-03：错误密码、重复用户名和非法参数均有可断言的失败结果。
- AC01-04：普通用户访问 `/api/admin/users` 返回业务权限拒绝；管理员访问成功。
- AC01-05：需求、`SYS01`、Controller/Service、`UNIT01/INT01/E2E01` 可以互相追溯。

## REQ02 / UC02 用户资料和地址

### 业务目标

允许用户维护自己的公开资料和收货地址，保证地址归属、默认地址和删除权限正确。

### 参与者、触发与前置条件

- 参与者：已登录普通用户、官方卖家。
- 触发条件：用户打开个人资料或地址管理，执行查询、新增、修改、删除。
- 前置条件：JWT 有效；用户记录存在；地址字段满足格式校验。

### 主成功流程

1. 用户查询 `/api/user/profile` 或 `/api/user/me`。
2. 用户提交资料修改，系统更新本人资料。
3. 用户新增地址并指定是否为默认地址。
4. 系统返回本人地址列表；用户可修改或删除本人地址。
5. 设为默认地址时，系统清除本人其他默认地址。

### 备选与异常流程

- 未登录访问资料或地址接口：拒绝请求。
- 手机号、收件人或地址必填字段不合法：拒绝保存。
- 修改/删除他人地址：拒绝，不改变数据库。
- 删除不存在的地址：返回明确业务错误。
- 多个地址被设为默认：系统最终只保留一个本人默认地址。

### 可验证结果与验收条件

- AC02-01：资料查询和修改只影响当前用户。
- AC02-02：新增地址可在本人列表中查询，修改后字段一致。
- AC02-03：默认地址规则可通过数据库或 API 查询验证。
- AC02-04：删除地址后再次查询不应出现该地址。
- AC02-05：`SYS02`、`UserController/UserServiceImpl`、`UNIT02/INT02/E2E02` 可追溯。

## REQ03 / UC03 商家申请、通过和拒绝

### 业务目标

允许普通用户提交商家入驻申请，由管理员审核；审核通过后升级为官方卖家，拒绝时保存原因并保持原角色。

### 参与者、触发与前置条件

- 参与者：普通用户、管理员、商家申请服务、通知服务。
- 触发条件：用户提交入驻申请；管理员打开申请列表并选择通过或拒绝。
- 前置条件：用户已登录且未拥有有效商家申请/官方卖家角色；管理员已登录；申请字段完整。

### 主成功流程

1. 用户提交店名、主营分类、身份证号、银行卡号、营业执照地址、仓库和联系人信息。
2. 系统保存 `merchant_application`，状态为待审核。
3. 管理员查询待审核申请。
4. 管理员选择通过，系统更新申请状态、升级用户角色并创建/更新店铺相关信息。
5. 或者管理员选择拒绝，系统保存拒绝原因，用户角色保持不变。
6. 系统写入管理员审计日志并按现有规则产生通知。

### 备选与异常流程

- 申请字段缺失或格式错误：拒绝提交。
- 已有待审核/已通过申请：禁止重复创建或给出明确状态提示。
- 非管理员审核：拒绝，不改变申请状态。
- 已处理申请再次通过/拒绝：拒绝重复状态转换。
- 审核后通知失败：不回滚核心审核结果，记录待补发状态或日志。

### 可验证结果与验收条件

- AC03-01：用户可以提交并查询自己的申请状态。
- AC03-02：管理员列表只允许管理员访问，能看到申请状态和申请人。
- AC03-03：拒绝分支保存原因且用户仍为原角色。
- AC03-04：通过分支升级为 `OFFICIAL_SELLER`，申请状态和审计日志一致。
- AC03-05：`SYS03`、`UserController/AdminMerchantApplicationController/MerchantApplicationServiceImpl`、`UNIT03/INT03/E2E03` 可追溯。

## REQ04 / UC04 用户封禁、解禁及审计

### 业务目标

允许管理员封禁和解禁普通用户，并确保封禁影响登录/访问，关键操作写入审计日志。

### 参与者、触发与前置条件

- 参与者：管理员、普通用户、认证服务、审计服务。
- 触发条件：管理员在用户管理中选择封禁或解禁。
- 前置条件：目标用户存在；当前操作人是 ADMIN；目标用户不是当前管理员账号。

### 主成功流程

1. 管理员查询用户列表并选择目标用户。
2. 管理员执行封禁，系统将用户状态设为 `BANNED`。
3. 被封禁用户再次登录时，系统拒绝登录。
4. 管理员执行解禁，系统将用户状态恢复为 `NORMAL`。
5. 用户重新登录成功；封禁与解禁分别写入 `admin_audit_log`。

### 备选与异常流程

- 非管理员尝试封禁/解禁：拒绝且不写入成功审计记录。
- 封禁不存在用户：返回明确错误。
- 管理员尝试封禁自己：界面和服务均应阻止。
- 重复封禁或重复解禁：保持幂等或返回明确状态提示。
- 旧 token 在封禁后继续调用受保护资源：按当前鉴权策略拒绝或在文档中明确 token 生存边界。

### 可验证结果与验收条件

- AC04-01：封禁后用户状态为 `BANNED`，登录业务结果为失败。
- AC04-02：解禁后用户状态为 `NORMAL`，重新登录成功。
- AC04-03：非管理员不能调用管理接口；管理员自己不能被误封禁。
- AC04-04：封禁、解禁审计记录包含操作者、动作、目标和时间。
- AC04-05：`SYS04`、`AdminUserController/AdminUserServiceImpl/AuthServiceImpl/AdminAuditLogServiceImpl`、`UNIT04/INT04/E2E04` 可追溯。

## REQ05 / UC05 举报、拉黑、信用分和审计

### 业务目标

提供用户之间的举报和拉黑能力，并允许管理员审核举报、调整信用分和追踪治理审计。

### 参与者、触发与前置条件

- 参与者：普通用户、官方卖家、管理员、举报/拉黑服务、信用服务、审计服务。
- 触发条件：用户从交易/用户入口提交举报或拉黑；管理员打开举报队列进行审核或信用调整。
- 前置条件：用户已登录；被举报/拉黑目标存在且不是非法目标；管理员账号可用。

### 主成功流程

1. 用户提交被举报用户、举报类型、说明和可选证据。
2. 系统保存 `user_report`，用户可查询本人举报记录。
3. 用户拉黑目标用户，系统保存 `user_block`；用户可查询、检查和解除拉黑。
4. 管理员查询待处理举报。
5. 管理员选择成立或驳回并填写备注；成立时按确认规则扣减对应信用分，或执行管理员信用调整。
6. 系统写入 `credit_score_log` 和 `admin_audit_log`。

### 备选与异常流程

- 举报自己、不存在用户或重复有效举报：拒绝并返回明确原因。
- 拉黑自己、重复拉黑、解除不存在关系：保持幂等或返回明确结果。
- 非管理员审核举报/调整信用分：拒绝。
- 举报已处理后再次审核：拒绝重复处理。
- 证据地址为空或格式不合法：按字段规则拒绝或作为无证据举报保存，规则需由教师确认。

### 可验证结果与验收条件

- AC05-01：举报记录包含举报人、目标、类型、说明、状态和时间。
- AC05-02：拉黑、查询状态、解除拉黑的结果与 `user_block` 一致。
- AC05-03：管理员可查询并审核举报，成立/驳回状态不可重复覆盖。
- AC05-04：信用分变化、信用变更日志和管理员审计日志可追溯；扣分规则以教师确认版本为准。
- AC05-05：`SYS05`、`ReportBlockController/AdminReportController/CreditController`、`UNIT05/INT05/E2E05` 可追溯。
