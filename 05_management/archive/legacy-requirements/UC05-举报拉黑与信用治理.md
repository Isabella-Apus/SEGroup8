# REQ05 / UC05 举报、拉黑与信用治理

## 业务目标

提供用户举报/拉黑能力，并由管理员审核举报、调整信用分和查询治理审计，保证治理结果、信用日志和操作日志可以追溯。

## 参与者、前置条件与触发

- 参与者：普通用户、官方卖家、管理员、举报/拉黑服务、信用服务、审计服务。
- 前置条件：用户已登录；举报或拉黑目标存在且不是当前用户；管理员账号有效。
- 触发：用户提交举报/拉黑，管理员审核举报或调整信用分。

## 接口与成功结果

| 方法 | 路径 | 结果 |
|---|---|---|
| POST | `/api/report-block/report` | 创建待审核举报 |
| GET | `/api/report-block/report/my` | 查询本人举报 |
| POST | `/api/report-block/block` | 建立拉黑关系 |
| DELETE | `/api/report-block/block/{targetUserId}` | 解除拉黑关系 |
| GET | `/api/report-block/block/my`、`check/{id}`、`blocked-by/{id}` | 查询拉黑关系 |
| GET | `/api/credit/me`、`/api/credit/{userId}` | 查询信用信息 |
| GET/POST | `/api/admin/reports`、`/audit` | 管理员查询/审核举报 |
| POST | `/api/admin/reports/credit-adjust?userId=&role=&delta=&remark=` | 管理员调整信用分 |

## 主成功流

1. 用户提交目标用户、举报类型、说明和交易场景。
2. 系统检查目标存在、不是自己，且不存在重复有效举报，写入待审记录。
3. 用户可以建立、查询或解除拉黑关系。
4. 管理员查看举报队列并提交成立/驳回决定。
5. 成立决定调用信用服务扣分并写入 `credit_score_log`；审核动作写入 `admin_audit_log`。
6. 用户查询本人或指定用户信用信息。

## 备选与异常流

- 未登录：用户治理接口返回 `401`。
- 自己举报/自己拉黑：返回 `400`。
- 目标用户不存在：返回 `404`。
- 已存在有效举报或拉黑关系：拒绝重复操作。
- 解除不存在的拉黑关系：返回明确业务错误。
- 非管理员查询/审核或调整信用：返回 `403`。
- 已审核举报再次审核：拒绝重复处理，不能重复扣分。
- 信用调整超出 0-100：返回 `400`，不写用户和信用日志。

## 可验证结果

- AC05-01：举报字段、状态和本人查询结果完整。
- AC05-02：拉黑、查询、解除结果一致，重复和自操作被拒绝。
- AC05-03：只有管理员可以审核，重复审核不会重复产生治理结果。
- AC05-04：信用分、信用日志、举报状态和管理员审计可追溯。
