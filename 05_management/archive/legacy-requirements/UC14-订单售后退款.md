# REQ14 / UC14 订单售后退款

## 业务目标

买家能够在规则允许的阶段申请仅退款或退货退款，卖家、管理员或超时任务能够作出可审计的同意/拒绝决定，并保证资金、库存、订单状态和售后日志一致。

## 参与者、触发条件和前置条件

- 主要参与者：订单买家、订单卖家、管理员。
- 协作参与者：超时退款定时任务、结算模块、通知与实时推送机制。
- 触发条件：买家提交退款申请；卖家或管理员处理申请；系统发现申请超过七天未处理。
- 前置条件：订单属于买家且已付款；订单未关闭；`can_refund=1`；当前退款状态为 `NONE(0)` 或 `REJECTED(3)`；退货退款还要求货物已到达，或订单处于收货后有效售后期。

## 主成功流程

1. 买家选择退款方式、填写原因和可选凭证并提交。
2. 系统校验订单状态、售后期限和退款状态机，将退款状态更新为 `PROCESSING(1)`。
3. 系统写入 `APPLY` 售后日志并通知订单卖家。
4. 卖家或管理员查看申请与历史日志并选择同意。
5. 系统将退款状态改为 `APPROVED(2)`、订单改为 `CLOSED(9)`，记录处理人、来源、说明和时间。
6. 系统将应退金额回流至买家个人余额；已结算订单同时从对应卖家账户扣回。
7. 系统写入退款交易流水和 `APPROVE` 售后日志，并通知买卖双方。

## 备选流程

- A1：待发货订单申请 `ONLY_REFUND` 时，系统自动同意、回补库存、关闭订单并记录系统决定。
- A2：卖家或管理员拒绝时，退款状态改为 `REJECTED(3)`，订单主状态保持不变；买家补充材料后可再次申请。
- A3：申请超过七天未处理时，定时任务以 `SYSTEM` 来源自动同意退款。
- A4：已发货但未到达时允许按规则申请仅退款；卖家同意后收到快递拦截提醒。

## 异常流程

- E1：未付款、已关闭、超过售后期或 `can_refund=0` 时拒绝申请。
- E2：未到货且不满足收货后售后期时，拒绝退货退款。
- E3：退款处理中重复申请，或非处理中执行同意/拒绝，返回业务错误。
- E4：非订单买家申请、非订单卖家处理或非管理员调用管理接口，返回 403。
- E5：同一版本被并发处理时，只有一次条件更新成功，不重复退款。
- E6：余额、交易流水或售后日志写入失败时，事务回滚。

## 可验证结果

| 验证通道 | 可验证结果 |
|---|---|
| 页面 | `AfterSaleView.vue`、`OrderDetailView.vue` 展示申请状态；`MerchantOrdersView.vue` 与管理端订单页展示处理入口、决定来源和说明。 |
| 接口 | 买家申请返回 `refundStatus=1`；同意返回 `refundStatus=2`、`orderStatus=9`；拒绝返回 `refundStatus=3`；管理端日志接口返回完整动作序列。 |
| 数据库 | `order_info` 保存原因、方式、状态、处理人/来源/说明/时间；`order_after_sale_log` 按动作留痕；`balance` 与 `transaction_record` 的退款金额一致；仅退款自动通过时库存回补。 |
| 日志 | 通知和实时事件可按订单 ID 追踪；定时任务失败记录告警；相同申请不会生成重复退款流水。 |

## 验收条件

- AC14-01：合法申请进入处理中并生成可审计日志。
- AC14-02：卖家、管理员和系统决定均保存正确的操作者、来源、说明与时间。
- AC14-03：退款资金、库存、订单状态和流水保持一致且不重复执行。
- AC14-04：拒绝后再申请、超时自动同意、越权和非法状态均有自动化可验证结果。
