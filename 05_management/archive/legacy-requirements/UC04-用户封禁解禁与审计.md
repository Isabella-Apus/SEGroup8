# REQ04 / UC04 用户封禁、解禁与审计

## 业务目标

允许管理员治理用户状态，封禁后阻止账号登录，解禁后恢复正常使用，并为关键动作留下可查询的审计记录。

## 参与者、前置条件与触发

- 参与者：管理员、普通用户、认证服务、审计服务。
- 前置条件：目标用户存在；当前操作者是 ADMIN；操作者不能是目标用户本人。
- 触发：管理员在用户治理页面执行封禁、解禁或查看审计日志。

## 接口与成功结果

| 方法 | 路径 | 结果 |
|---|---|---|
| GET | `/api/admin/users` | 管理员分页查询用户 |
| PUT | `/api/admin/users/{userId}/ban` | 目标状态改为 `BANNED` 并记录审计 |
| PUT | `/api/admin/users/{userId}/unban` | 目标状态恢复为 `NORMAL` 并记录审计 |
| GET | `/api/admin/audit-logs` | 管理员分页查询治理审计 |

## 主成功流

1. 管理员查询用户列表并选择目标用户。
2. 系统校验当前用户为 ADMIN，且目标不是当前管理员本人。
3. 封禁操作将 `user.status` 改为 `BANNED`，并写入 `admin_audit_log`。
4. 被封禁用户再次登录时被认证服务拒绝。
5. 管理员解禁后状态恢复为 `NORMAL`，并写入解禁审计。

## 备选与异常流

- 无 Token 或非 ADMIN：返回 `401/403`，不改用户状态。
- 目标用户不存在：返回 `404`。
- 管理员封禁自己：返回 `400`。
- 重复封禁/解禁：保持明确、幂等的状态结果。
- 封禁后使用旧 Token：后续资源授权必须按项目约定重新校验账号状态；该边界由回归测试确认。

## 可验证结果

- AC04-01：封禁后状态为 `BANNED`，登录业务失败。
- AC04-02：解禁后状态为 `NORMAL`，用户可以重新登录。
- AC04-03：非 ADMIN 不能执行治理操作，管理员不能封禁自己。
- AC04-04：封禁/解禁审计包含操作、目标和时间，可被管理员查询。
- AC04-05：需求、组件、代码、测试可由 `REQ04/UC04` 追溯到 `UNIT04/INT04`。
