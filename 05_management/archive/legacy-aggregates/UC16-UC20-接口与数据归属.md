# UC16-UC20 OpenAPI 接口、数据归属和调用约定

当前仓库主线仍是单体后端，所有接口统一挂在 `/api` 下，并可通过 SpringDoc 暴露 `/v3/api-docs` 和 `/swagger-ui.html`。第二阶段拆分微服务时，建议将 UC16-UC20 迁入独立的 `secondhand-trade-service`，订单履约继续通过订单服务协作。

## 前端调用约定

| 前端封装 | 后端接口 | 用例 | 备注 |
|---|---|---|---|
| `publishSecondhandApi` | `POST /secondhand/seller` | UC16 | 发布闲置 |
| `buySecondhandApi` | `POST /secondhand/{id}/buy` | UC17 | 直接购买 |
| `applyBargainApi` / `confirmBargainApi` / `rejectBargainApi` | bargain 系列接口 | UC18 | 买家议价、卖家同意或拒绝 |
| `createAuctionApi` / `placeAuctionBidApi` | auction 系列接口 | UC19 | 发起拍卖、参与竞拍 |
| `getSoldSecondhandOrderListApi` / `shipOrderApi` / `confirmReceiveOrderApi` | order 系列接口 | UC20 | 履约闭环 |

前端 `getSecondhandCategoryTreeApi` 调用 `/category/tree?scene=SECONDHAND`。本次已在 mock 层补齐该路由，`scene=SECONDHAND` 时返回二手分类树；真实后端存在 `CategoryController` 时也应保持同名接口和相同字段结构。

## 表归属

| 表 | 当前写入模块 | 归属建议 | 说明 |
|---|---|---|---|
| `secondhand_product` | SecondhandProductService | secondhand-trade-service | 二手商品主表，保存卖家、价格、成色、状态 |
| `product_negotiation` | SecondhandTradeService | secondhand-trade-service | 议价请求、状态和生成订单关联 |
| `product_auction` | SecondhandTradeService / AuctionSettlementScheduler | secondhand-trade-service | 拍卖主表，保存当前价、领先买家和状态 |
| `auction_log` | SecondhandTradeService | secondhand-trade-service | 出价流水 |
| `order_info` | OrderService | order-service | 订单主表，二手订单通过 `order_item.product_type=SECONDHAND` 识别 |
| `order_item` | OrderService | order-service | 订单明细，保存二手商品 ID、名称、价格和卖家 |
| `logistics_trace` | LogisticsService / OrderService | logistics/order-service | 二手订单发货和物流轨迹 |
| `notification` | NotificationService / OrderService | notification-service | 发货、订单状态等通知 |

## 状态与关键规则

- 二手商品仅允许卖家本人发布、编辑、上下架和删除。
- 买家不能购买、议价或竞拍自己的二手商品。
- 直接购买和卖家同意义价都应创建 `PENDING_PAY(0)` 订单；买家支付后才进入 `PENDING_SHIP(1)`。
- 卖家发货后订单进入 `SHIPPED(2)`；买家确认收货后进入 `RECEIVED(3)`，后续评价完成后进入 `COMPLETED(4)`。
- 拍卖只能有一个进行中的同商品拍卖；历史拍卖不应阻止再次发起新拍卖。
- 出价必须不低于当前价加加价幅度；拍卖关闭或流拍后不可继续出价。
- 跨服务拆分后，二手交易服务不得直接写订单表，应通过订单服务接口创建二手订单并保存补偿/重试记录。
