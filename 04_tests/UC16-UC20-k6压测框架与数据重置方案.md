# UC16-UC20 k6 压测框架与数据重置方案

## 目标

成员 D 负责二手交易域，需要为后续单体版本和微服务版本的性能对比提前准备统一压测框架。压测对象按计划固定为三类：

| 对象 | 对应用例/领域 | 脚本 |
|---|---|---|
| 商品搜索 | 商品搜索与二手搜索对比 | `04_tests/performance/k6/product-search.k6.js` |
| 新品下单 | 新品订单创建链路 | `04_tests/performance/k6/new-order-create.k6.js` |
| 二手购买或拍卖出价 | UC17/UC19 二手成交链路 | `04_tests/performance/k6/secondhand-buy.k6.js` 或 `04_tests/performance/k6/secondhand-auction-bid.k6.js` |

## 固定运行条件

- 单体版本和微服务版本必须使用同一台机器、同一数据库规模、同一账号、同一压测脚本。
- 每个接口至少运行三轮，保留原始 CSV/JSON 输出。
- 记录吞吐量、平均响应时间、P95、错误率、CPU/内存、Pod 数量。
- 不用压测结果直接写“性能提升”，必须等三轮原始数据支持。

## 数据重置方案

当前单体后端已经提供 reset-all 启动方案：

```powershell
cd backend
.\start-reset.ps1
```

该脚本会使用 `SPRING_PROFILES_ACTIVE=reset-all`，按 `application-reset-all.yml` 加载：

```text
classpath:data-reset-all.sql
classpath:data.sql
```

重置原则：

- 每轮正式压测前先停止后端，再用 reset-all 重新启动。
- 记录启动时间、Git commit、数据库脚本版本和测试账号。
- 对会消耗状态的数据，例如订单、二手直接购买、拍卖出价，必须每轮重置后再跑。
- 如果使用 `secondhand-buy.k6.js`，需要准备多个在售二手商品 ID，避免同一商品售出后后续请求全部转为业务拒绝。
- 如果使用 `secondhand-auction-bid.k6.js`，需要先准备进行中的拍卖 ID，并设置足够高的 `BID_BASE_AMOUNT` 和 `BID_STEP`，降低并发竞价互相压低导致的业务拒绝。

## 推荐命令

### 商品搜索

```powershell
k6 run `
  -e BASE_URL=http://127.0.0.1:8080/api `
  -e VUS=20 `
  -e DURATION=1m `
  -e KEYWORD=耳机 `
  .\04_tests\performance\k6\product-search.k6.js
```

### 新品下单

```powershell
k6 run `
  -e BASE_URL=http://127.0.0.1:8080/api `
  -e VUS=5 `
  -e DURATION=30s `
  -e BUYER_USERNAME=user `
  -e BUYER_PASSWORD=user123 `
  -e NEW_PRODUCT_ID=1 `
  -e ADDRESS_ID=1 `
  .\04_tests\performance\k6\new-order-create.k6.js
```

### 二手拍卖出价

```powershell
k6 run `
  -e BASE_URL=http://127.0.0.1:8080/api `
  -e VUS=10 `
  -e DURATION=30s `
  -e BUYER_USERNAME=user `
  -e BUYER_PASSWORD=user123 `
  -e AUCTION_ID=1 `
  -e BID_BASE_AMOUNT=200 `
  -e BID_STEP=10 `
  .\04_tests\performance\k6\secondhand-auction-bid.k6.js
```
