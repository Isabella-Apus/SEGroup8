## 发现的基线缺陷

### D-PERF-01 二手订单号在同一买家一秒内发生碰撞

- 对应用例：UC17 / Issue `#56`。
- 现象：二手购买 HTTP 均正常返回，但高频请求中只有 13.79% 真正创建订单，其余进入业务保护。
- 后端原始原因：MySQL 唯一键 `order_info.uk_order_info_order_no` 报重复，例如 `SND202608262121230002`。
- 根因：`monolith-start` 使用“秒级时间 + 买家 ID 后四位”生成二手订单号，同一买家一秒内只能成功创建一笔。
- 处理：保留基线原始结果；在 UC17 的现有 PR `#128` 中增加唯一订单号修复与并发回归测试，不修改 `monolith-start` 标签。

拍卖场景最初因测试账号无余额而被拒绝。补齐专用余额、为两个 VU 分配独立账号和拍卖后，最终首轮达到 100% 业务成功，说明数据重置前置条件有效。
