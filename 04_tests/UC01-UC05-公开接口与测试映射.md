## 判定口径

- “Day 3 API”包括 Controller 的 MockMvc 契约测试、参数校验、权限分支、Service 单元规则和 JWT 校验契约；每项必须有有效响应断言或状态/调用断言。
- “Day 4/E2E”包括前端到后端的真实登录、多用户真实数据库、跨接口状态变化和跨服务链路；本文件只登记待办，不把它们误记为 Day 3 API 缺口。
- 当前 Controller 测试多数使用 standalone MockMvc，因此“API 已覆盖”表示路由/参数/响应/委托契约已覆盖，不等于真实数据库 E2E 已完成。

## 统一 API 验收规则

- 成功和业务失败都要检查 `code`、`message` 和 `data`，不能只检查 HTTP 200。
- 受保护接口的 Controller/API 测试至少覆盖正常委托、参数失败或非管理员拒绝；JWT 拦截器单独覆盖缺失、有效和非法 Token。
- 修改类接口的 Service 测试检查重复请求、非法状态、自操作和越权目标。
- 每个接口必须在最终 OpenAPI 清单中保留负责人、测试编号和证据链接。
